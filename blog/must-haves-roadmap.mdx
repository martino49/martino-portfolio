## Why I'm publishing this

A job spec from a recruiter landed in my feed: software developers and engineers, 5+ years of experience, production software, testing discipline, AI-assisted development, a required GitHub profile. The requirements were specific enough that they read like a rubric.

Most people would tailor a CV to that rubric. I'm doing something more useful: turning it into a public tracker. Every item below is either backed by a live, clickable link or marked as a gap with a date attached. If you're a recruiter or a client reading this, this page *is* the audit trail — judge me by the links, not by adjectives.

The one rule I've kept from my portfolio config applies here too: **I don't claim years of experience I don't have. I claim what ships.**

## The checklist

### Where I stand today — live evidence, not claims

| Requirement | Evidence |
|---|---|
| **Production-level software** | [FinMate](https://fin-mate-three.vercel.app) — 5-role RBAC finance platform, live on Vercel, auto-migrating schema on boot. [EduLMS](https://edulms-iota.vercel.app) — 5-role LMS with grading, attendance, fee payments. |
| **Strong proficiency in one language** | TypeScript and JavaScript across the whole stack (Node.js, Express, React); Kotlin for the Android work. |
| **Relational databases & queries** | MySQL, PostgreSQL, Supabase. Schema design, joins, indexing, query optimization on 10–30 table systems. |
| **REST API design & consumption** | Express REST APIs in every project, plus real payment APIs: M-Pesa (Daraja STK), Paystack, PayPal, Stripe. I write and consume them. |
| **Version control (Git) & GitHub** | My entire workflow — feature branches, meaningful commits, PR review with the collaborators I build with. |
| **Testing & code quality** | Jest + supertest integration suites (EduLMS passes end-to-end), input validation, helmet CSP, rate limiting on auth. |
| **SDLC discipline** | Requirements → build → test → deploy → maintain. The maintenance half is the part tutorials skip and I don't. |
| **Written & spoken English** | Fluent. This post is the sample. |

### Actively building toward

- **AI-assisted development** — the spec asks for familiarity with AI tools, and I use them daily. So I'm doing more than using them: a written series on where AI genuinely helps in a full-stack workflow (API scaffolds, test scaffolding, refactor review) and where it hallucinates and costs time. Using a tool is familiarity; teaching it is proof.
- **OOP & design patterns applied deliberately** — I can build working software, but I want the diagrams to be as deliberate as the code. Ongoing refactor of one backend into explicit layered architecture, documented in the repo README, so a reviewer can see the structure, not just the result.
- **Containers & deployment environments** — Dockerizing one service end to end (compose, healthchecks, env parity) and deploying it publicly. Vercel is comfortable; I want the part Vercel hides from me.
- **Reading existing codebases** — the fastest way to prove this is to read other people's code *in public*: open-source PRs and code reviews, not just repos I started myself.

### The honest gap

**5+ years of professional experience.** I can't fabricate it and I won't reword my way around it. I'm roughly two years into that path — Year 2 of a BSIT at Karatina University, full-stack training at Eldohub completed in August 2025, one paid client delivery, and everything shipped since.

So here's my aim, stated plainly: **build the evidence that five years produces** — one production system maintained publicly for twelve consecutive months, visible releases, visible maintenance commits, visible bug fixes on live software. Anyone can claim five years. Maintained release history is how I'll demonstrate it. This checklist will be updated quarterly, and the gap stays on the page until the evidence closes it.

## How this stays honest

- Every claim above links to something live. Dead links get fixed or the claim comes down.
- The gap section never gets deleted quietly — it gets dated.
- This checklist is versioned with the portfolio that hosts it.

If you're hiring against a spec like this one, start with the evidence links. That's what they're for.
